# AWS CodeBuild - Basic Interview Questions

### Q1: What is AWS CodeBuild?
**Level:** L1 | **Category:** conceptual
**Target Services:** CodeBuild

> **Quick Answer:** AWS CodeBuild is a fully managed continuous integration service that compiles source code, runs tests, and produces software packages that are ready to deploy.

#### Detailed Answer
CodeBuild eliminates the need to provision, manage, and scale your own build servers. It scales continuously and processes multiple builds concurrently, so your builds are not left waiting in a queue. You pay only for the compute time you use.

#### Follow-up Questions
- How is CodeBuild billed?
- What environments are supported by CodeBuild?

### Q2: What is a `buildspec.yml` file?
**Level:** L1 | **Category:** conceptual
**Target Services:** CodeBuild

> **Quick Answer:** A buildspec is a collection of build commands and related settings, in YAML format, that CodeBuild uses to run a build.

#### Detailed Answer
It must be named `buildspec.yml` and placed in the root of the source directory by default, though you can specify a different name or location. It defines the phases of the build (install, pre_build, build, post_build), environment variables, and the artifacts to be exported.

#### Follow-up Questions
- Can you override the buildspec file when starting a build?

### Q3: What are the main phases defined in a buildspec file?
**Level:** L2 | **Category:** practical
**Target Services:** CodeBuild

> **Quick Answer:** The typical phases are `install`, `pre_build`, `build`, and `post_build`.

#### Detailed Answer
- **install**: Used for installing dependencies (e.g., `npm install`, `pip install`).
- **pre_build**: Tasks before the main build, like logging into Docker registries (ECR).
- **build**: The core compilation or testing commands (e.g., `mvn package`, `docker build`).
- **post_build**: Actions after the build, like pushing Docker images to a registry or creating an artifact zip.

### Q4: How does CodeBuild handle Docker images?
**Level:** L2 | **Category:** practical
**Target Services:** CodeBuild, ECR

> **Quick Answer:** CodeBuild can run builds inside custom Docker images and can also build and push Docker images to registries like Amazon ECR.

#### Detailed Answer
To build Docker images, the CodeBuild project must be run in privileged mode. The `buildspec.yml` typically logs into ECR in the `pre_build` phase, builds the image in the `build` phase, and pushes it to ECR in the `post_build` phase.

#### Follow-up Questions
- What happens if you forget to enable privileged mode? (Docker daemon fails to start).

### Q5: How do you pass secrets to CodeBuild securely?
**Level:** L2 | **Category:** security
**Target Services:** CodeBuild, Secrets Manager, Parameter Store

> **Quick Answer:** Use AWS Systems Manager Parameter Store or AWS Secrets Manager and reference them in the `env` section of the buildspec.

#### Detailed Answer
In the `buildspec.yml`, under `env:`, you can define `parameter-store:` or `secrets-manager:`. CodeBuild will fetch these values securely at runtime. The CodeBuild service role must have IAM permissions to access those specific secrets. 

### Q6: How do you cache dependencies in CodeBuild to speed up builds?
**Level:** L2 | **Category:** cost-optimization
**Target Services:** CodeBuild, S3

> **Quick Answer:** You configure caching in the project settings to use either local caching (on the build host) or Amazon S3 caching.

#### Detailed Answer
- **Local caching**: Caches Docker layers, source code, or custom directories directly on the host instance. Fastest, but cache misses happen if a new instance is spun up.
- **S3 caching**: Stores the cache in an S3 bucket. Slower than local but shared across all build instances. You specify the directories to cache in the `cache:` block of the `buildspec.yml`.

### Q7: What are CodeBuild Artifacts?
**Level:** L1 | **Category:** conceptual
**Target Services:** CodeBuild, S3

> **Quick Answer:** Artifacts are the output files generated by the build process, which CodeBuild can upload to an S3 bucket or pass back to CodePipeline.

#### Detailed Answer
In the `artifacts:` phase of the `buildspec.yml`, you define `files` (the paths to the files to include) and optionally a `base-directory`. If used within CodePipeline, CodeBuild automatically packages these files and places them in the pipeline's artifact bucket.

### Q8: How can you run tests and view reports in CodeBuild?
**Level:** L2 | **Category:** practical
**Target Services:** CodeBuild

> **Quick Answer:** CodeBuild supports Test Reports. You output test results in JUnit XML, Cucumber JSON, or other supported formats, and specify them in the `reports:` section of the buildspec.

#### Detailed Answer
When specified, CodeBuild parses these report files and generates a visual dashboard in the AWS Console, showing pass/fail rates, duration, and specific failing test cases.

### Q9: Can you access VPC resources from CodeBuild?
**Level:** L2 | **Category:** architecture
**Target Services:** CodeBuild, VPC

> **Quick Answer:** Yes, you can configure a CodeBuild project to run within a specific VPC, providing subnets and security groups.

#### Detailed Answer
By placing CodeBuild in a VPC, it gets an Elastic Network Interface (ENI) in the specified subnet. This allows the build to access private resources like RDS databases, internal APIs, or ElastiCache clusters. Note that to access the internet (e.g., to download public packages), the subnet must be private with a route to a NAT Gateway.

### Q10: What is CodeBuild Local?
**Level:** L2 | **Category:** troubleshooting
**Target Services:** CodeBuild

> **Quick Answer:** CodeBuild Local is a Docker image provided by AWS that allows you to run CodeBuild builds on your local machine.

#### Detailed Answer
It is highly useful for troubleshooting and debugging `buildspec.yml` files without having to commit code and wait for a remote build to spin up. It simulates the AWS CodeBuild environment locally.

### Q11: How do you handle environment variables in CodeBuild?
**Level:** L1 | **Category:** practical
**Target Services:** CodeBuild

> **Quick Answer:** Environment variables can be defined in the CodeBuild project settings, in the `buildspec.yml` file, or passed at runtime when starting the build.

#### Detailed Answer
Variables defined at runtime override project-level variables, which override buildspec-level variables. CodeBuild also provides default environment variables (like `CODEBUILD_BUILD_ID`, `CODEBUILD_SOURCE_VERSION`) that are available during the build.

### Q12: What happens if a command in the build phase fails?
**Level:** L2 | **Category:** troubleshooting
**Target Services:** CodeBuild

> **Quick Answer:** By default, if any command in a phase returns a non-zero exit code, the phase fails, and the build transitions to the `post_build` phase and ultimately fails.

#### Detailed Answer
You can use `finally:` blocks within phases to ensure certain commands (like cleanup) run regardless of whether the preceding commands succeeded or failed.

### Q13: What compute types does CodeBuild offer?
**Level:** L2 | **Category:** architecture
**Target Services:** CodeBuild

> **Quick Answer:** CodeBuild offers various compute types (e.g., BUILD_GENERAL1_SMALL, MEDIUM, LARGE, 2XLARGE) on x86, ARM (Graviton), and GPU architectures.

#### Detailed Answer
Selecting the right compute type impacts build speed and cost. For example, large Java or C++ compilations benefit from larger instances, while simple scripting tasks can run on small instances. AWS Graviton instances often provide better price/performance.

### Q14: How does CodeBuild integrate with GitHub?
**Level:** L2 | **Category:** practical
**Target Services:** CodeBuild

> **Quick Answer:** You can connect CodeBuild directly to GitHub using OAuth or Personal Access Tokens, and use Webhooks to trigger builds on push or pull requests.

#### Detailed Answer
When connected, CodeBuild can automatically report build statuses back to GitHub (e.g., showing a green checkmark on a PR if the build passes).

### Q15: How can you prevent CodeBuild from timing out?
**Level:** L2 | **Category:** limits
**Target Services:** CodeBuild

> **Quick Answer:** You can increase the build timeout setting in the CodeBuild project configuration.

#### Detailed Answer
The default timeout is often 60 minutes, but it can be increased up to 8 hours. If builds are taking that long, it's recommended to optimize them (e.g., caching, breaking them into smaller builds, using larger compute instances).
