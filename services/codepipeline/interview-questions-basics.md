# AWS CodePipeline - Basic Interview Questions

### Q1: What is AWS CodePipeline and what problem does it solve?
**Level:** L1 | **Category:** conceptual
**Target Services:** CodePipeline

> **Quick Answer:** AWS CodePipeline is a fully managed continuous delivery service that automates the release pipelines for fast and reliable application and infrastructure updates.

#### Detailed Answer
CodePipeline automates the build, test, and deploy phases of a release process every time a code change occurs. It integrates with various AWS and third-party tools to orchestrate the entire software delivery lifecycle, removing manual steps and reducing human error.

#### Follow-up Questions
- How does CodePipeline differ from Jenkins?
- Can CodePipeline run tasks in parallel?

#### References
- [AWS CodePipeline Features](https://aws.amazon.com/codepipeline/features/)

### Q2: What are the main components of an AWS CodePipeline?
**Level:** L1 | **Category:** conceptual
**Target Services:** CodePipeline

> **Quick Answer:** The main components are Pipelines, Stages, Actions, and Artifacts.

#### Detailed Answer
- **Pipeline**: The workflow describing the release process.
- **Stage**: A group of one or more actions.
- **Action**: A specific task (e.g., source, build, deploy).
- **Artifacts**: Files generated by an action and used by subsequent actions, stored in an S3 bucket.

#### Follow-up Questions
- How do artifacts pass between stages?

### Q3: How does CodePipeline pass data between different actions?
**Level:** L2 | **Category:** conceptual
**Target Services:** CodePipeline, S3

> **Quick Answer:** Data is passed between actions using an Amazon S3 artifact bucket configured for the pipeline.

#### Detailed Answer
When an action produces output (like compiled code), it zips it and uploads it to the pipeline's configured S3 artifact bucket as an Output Artifact. The next action in the pipeline downloads this zip file as its Input Artifact to process it.

#### Follow-up Questions
- How is security managed for these artifacts?
- Can an action have multiple input artifacts?

### Q4: Which Source providers are supported natively by CodePipeline?
**Level:** L2 | **Category:** practical
**Target Services:** CodePipeline

> **Quick Answer:** Natively supported source providers include AWS CodeCommit, Amazon S3, Amazon ECR, GitHub (via CodeStar connections), and Bitbucket.

#### Detailed Answer
CodePipeline can automatically trigger when changes occur in these source repositories. For GitHub and Bitbucket, AWS recommends using AWS CodeStar Connections for secure integration rather than the older OAuth method. ECR can trigger a pipeline when a new Docker image is pushed.

#### Follow-up Questions
- How do you trigger a pipeline from an unsupported Git repository?

### Q5: How do you implement a manual approval step in CodePipeline?
**Level:** L2 | **Category:** practical
**Target Services:** CodePipeline, SNS

> **Quick Answer:** You add an action of type `Manual Approval` to a stage and optionally configure an Amazon SNS topic to notify approvers.

#### Detailed Answer
A manual approval action halts the pipeline execution at that point until an authorized IAM user approves or rejects it. You can configure it to send an SNS notification with a link to review the changes. If rejected, the pipeline execution fails.

#### Follow-up Questions
- What happens if an approval action times out? (It defaults to rejected after 7 days)

### Q6: Can you run multiple actions concurrently within a CodePipeline stage?
**Level:** L2 | **Category:** architecture
**Target Services:** CodePipeline

> **Quick Answer:** Yes, actions within the same stage can run concurrently if they don't depend on each other.

#### Detailed Answer
When you add multiple actions to a single stage, they run in parallel by default. This is useful for running independent test suites concurrently or deploying to multiple regions simultaneously. To run them sequentially, they must be placed in different stages, or you must configure run order within the stage.

#### Follow-up Questions
- How do you configure sequential actions within the same stage?

### Q7: What triggers a pipeline execution automatically?
**Level:** L2 | **Category:** conceptual
**Target Services:** CodePipeline, EventBridge

> **Quick Answer:** A pipeline is typically triggered by changes in its source location, often using Amazon EventBridge rules or webhooks.

#### Detailed Answer
When using AWS services like CodeCommit, S3, or ECR, EventBridge rules are typically created to listen for change events and trigger the pipeline. For third-party repos like GitHub, webhooks are used. You can also trigger pipelines manually via the console, CLI, or an API call (`StartPipelineExecution`).

#### Follow-up Questions
- Can you schedule a pipeline execution?

### Q8: What is a CodePipeline Action Type?
**Level:** L1 | **Category:** conceptual
**Target Services:** CodePipeline

> **Quick Answer:** Action types define the category of the task, such as Source, Build, Test, Deploy, Approval, or Invoke.

#### Detailed Answer
Each stage must contain actions of appropriate types. For example, the first stage must contain only Source actions. The `Invoke` action type is used to trigger AWS Lambda functions or Step Functions state machines for custom logic.

#### Follow-up Questions
- What are some examples of tools used in the Test action type?

### Q9: How can you integrate a custom third-party tool into CodePipeline?
**Level:** L2 | **Category:** architecture
**Target Services:** CodePipeline, Lambda

> **Quick Answer:** You can integrate third-party tools by creating a Custom Action or by using an `Invoke` action to trigger an AWS Lambda function.

#### Detailed Answer
If a native integration doesn't exist, an AWS Lambda function can be invoked by CodePipeline. The Lambda function can interact with the external tool's API and then call the `PutJobSuccessResult` or `PutJobFailureResult` CodePipeline API to report the outcome.

#### Follow-up Questions
- What is the timeout limit for a Lambda action in CodePipeline?

### Q10: How does CodePipeline handle deployment failures?
**Level:** L2 | **Category:** troubleshooting
**Target Services:** CodePipeline

> **Quick Answer:** If an action fails, the pipeline execution halts at that action.

#### Detailed Answer
The failure prevents the changes from progressing to subsequent stages. You can inspect the logs (e.g., CodeBuild logs or CodeDeploy events) to diagnose the issue. Once fixed, you can retry the failed action or release the change again from the source.

#### Follow-up Questions
- Can CodePipeline automatically rollback on failure? (No, but the deployment tool like CodeDeploy might).

### Q11: What is the purpose of the CodePipeline Service Role?
**Level:** L2 | **Category:** security
**Target Services:** CodePipeline, IAM

> **Quick Answer:** The Service Role provides CodePipeline with the permissions necessary to interact with other AWS services.

#### Detailed Answer
CodePipeline assumes this IAM role to perform tasks such as reading from or writing to the artifact S3 bucket, starting CodeBuild jobs, triggering CodeDeploy, and passing roles to these services. It must have the `iam:PassRole` permission to allow other services to assume their respective roles.

#### Follow-up Questions
- What happens if the service role lacks permissions for the S3 artifact bucket?

### Q12: How can you pass environment variables or parameters dynamically to a build stage?
**Level:** L2 | **Category:** practical
**Target Services:** CodePipeline, CodeBuild

> **Quick Answer:** You can use CodePipeline variables to pass dynamic data between stages.

#### Detailed Answer
Actions in a pipeline can produce variables (e.g., the commit ID from a Source action). You can reference these variables in subsequent actions, for example, passing them as environment variables to a CodeBuild project using the syntax `#{Namespace.VariableName}`.

#### Follow-up Questions
- Where are the output variables for an action documented?

### Q13: What happens to a running pipeline if you edit its structure?
**Level:** L2 | **Category:** practical
**Target Services:** CodePipeline

> **Quick Answer:** The pipeline update doesn't stop current executions, but subsequent executions will use the new structure.

#### Detailed Answer
In-progress executions will continue using the structure that existed when they started. However, if the update deletes a stage that an active execution hasn't reached yet, that execution might fail when it attempts to transition to the deleted stage.

### Q14: How can you cross account deploy using CodePipeline?
**Level:** L2 | **Category:** architecture
**Target Services:** CodePipeline, IAM, KMS

> **Quick Answer:** You configure the pipeline to assume an IAM cross-account role in the target account and use a Customer Managed KMS Key for the artifact bucket.

#### Detailed Answer
The pipeline in Account A needs permission to assume a role in Account B. The artifact bucket in Account A must have a bucket policy allowing Account B to access it. Furthermore, the artifacts must be encrypted with a Customer Managed KMS key that both accounts have permission to use, because default AWS managed keys cannot be shared across accounts.

### Q15: What is the maximum number of stages allowed in CodePipeline?
**Level:** L1 | **Category:** limits
**Target Services:** CodePipeline

> **Quick Answer:** A single pipeline can have a maximum of 50 stages.

#### Detailed Answer
While 50 is the maximum, keeping pipelines concise is a best practice. If a pipeline requires more stages, it might be an indicator that the deployment process is too monolithic and should be broken down into microservices or smaller decoupled pipelines.

#### Follow-up Questions
- What is the maximum number of actions per stage? (50)
