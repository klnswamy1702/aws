# AWS Certificate Manager: Basics & Core Concepts

### Q1: What is the primary purpose of AWS Certificate Manager (ACM)?
**Level:** L1 | **Category:** conceptual
**Target Services:** ACM

> **Quick Answer:** ACM is used to provision, manage, and automatically renew public and private SSL/TLS certificates for securing network communications.

#### Detailed Answer
It removes the heavy lifting of purchasing, uploading, and renewing SSL/TLS certificates manually. For public certificates, the service is free; you only pay for the AWS resources you create to run your application.

### Q2: Can I download the private key of a public certificate generated by ACM?
**Level:** L1 | **Category:** security
**Target Services:** ACM

> **Quick Answer:** No, you cannot extract or download the private key for public certificates issued by ACM.

#### Detailed Answer
This is a security feature. The private keys are securely generated and managed by AWS Key Management Service (KMS). You deploy the certificate by attaching it directly to supported AWS services like ALBs, API Gateway, or CloudFront. If you need a certificate on an EC2 instance directly, you must use a third-party CA or AWS Private CA.

### Q3: Which AWS services integrate directly with ACM?
**Level:** L2 | **Category:** architecture
**Target Services:** ACM, ALB, CloudFront, API Gateway

> **Quick Answer:** The most common integrations are Elastic Load Balancing (ALB/NLB), Amazon CloudFront, Amazon API Gateway, AWS Elastic Beanstalk, and AWS AppSync.

#### Detailed Answer
You attach the ACM certificate to these services to terminate SSL/TLS traffic. For example, an ALB terminates the HTTPS connection from the client using the ACM certificate, and then can optionally forward the traffic to backend EC2 instances over unencrypted HTTP (reducing CPU load on the instances).

### Q4: Why is my ACM certificate in `eu-west-1` not showing up when configuring Amazon CloudFront?
**Level:** L2 | **Category:** troubleshooting
**Target Services:** ACM, CloudFront

> **Quick Answer:** Amazon CloudFront is a global service that requires ACM certificates to be provisioned specifically in the `us-east-1` (N. Virginia) region.

#### Detailed Answer
If you create a certificate in any other region (e.g., `eu-west-1`), CloudFront will not be able to see or attach it. You must request a new certificate for the same domain in the `us-east-1` region.

### Q5: What is the difference between DNS validation and Email validation?
**Level:** L1 | **Category:** practical
**Target Services:** ACM, Route 53

> **Quick Answer:** DNS validation requires you to add a CNAME record to your DNS configuration, while Email validation sends an approval link to the domain owner's registered email addresses.

#### Detailed Answer
**DNS Validation is highly recommended.** If you use Amazon Route 53, ACM can automatically create the CNAME record for you. More importantly, DNS validation enables automatic, hands-free renewal of the certificate as long as the CNAME record remains in place. Email validation requires clicking a link in an email every year to renew.

### Q6: Can I import an existing SSL/TLS certificate into ACM?
**Level:** L1 | **Category:** practical
**Target Services:** ACM

> **Quick Answer:** Yes, you can import third-party certificates into ACM.

#### Detailed Answer
If you bought a certificate from GoDaddy or DigiCert, you can import the certificate body, private key, and certificate chain into ACM. However, imported certificates **do not** auto-renew. You are responsible for monitoring their expiration and importing the renewed certificate before it expires.

### Q7: What happens during the automatic renewal of a DNS-validated certificate?
**Level:** L2 | **Category:** architecture
**Target Services:** ACM

> **Quick Answer:** ACM will automatically verify the DNS CNAME record 60 days prior to expiration. If verified, it issues a new certificate and seamlessly updates the AWS resources using it without downtime.

#### Detailed Answer
You do not need to update your ALBs or CloudFront distributions. ACM handles the deployment of the new certificate seamlessly.

### Q8: What is AWS Private CA?
**Level:** L2 | **Category:** conceptual
**Target Services:** ACM PCA

> **Quick Answer:** AWS Private CA is a highly available, managed private certificate authority service for creating and managing private certificates for internal use.

#### Detailed Answer
Unlike public ACM certificates, Private CA allows you to export the private key. This means you can install these private certificates on EC2 instances, on-premises servers, or IoT devices to secure internal communications (e.g., mTLS between microservices). Private CA is a paid service with a monthly fee per CA.
